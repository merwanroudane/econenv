# EconLang

> Write econometrics, not software syntax.

The same OLS is written five different ways in five programs. EconEnv already
lets you run all of them in one notebook; EconLang lets you *state the model
once* and change only which engine runs it.

```econ
data "macro.csv"

set time:
    variable = year
    frequency = quarterly

model ols baseline:
    y = gdp
    x = inflation, unemployment
    vcov = HC3
```

```python
from econenv import lang

result = lang.run_file("analysis.econ")
result.models["baseline"]        # an ordinary ModelResult
```

Or in a notebook:

```python
%%econlang
data "macro.csv"

model ols baseline:
    y = gdp
    x = inflation
```

The estimated models land in Python under the names you gave them, so
`baseline` is a `ModelResult` afterwards and everything EconEnv already does
with one — export, comparison, snapshots — works on it unchanged.

## This is a layer, not a replacement

`%%stata`, `%%R`, `%%eviews`, `%%matlab`, `%%gauss` and `%econ` are untouched
and always will be. EconLang covers the common path; the native magics remain
the escape hatch for anything an engine can do that the language cannot yet
express.

## How it works

Not a translator. Source becomes an abstract syntax tree, the tree becomes a
neutral **Econometric IR**, and only then does a backend see anything:

```
source → lexer → parser → AST → lowering → Econometric IR
       → capability check → engine → unified ModelResult
```

The IR is a `ModelSpec` — the same object `compare_ols` already hands to all six
engines. That is what makes this a runtime rather than a phrasebook: adding a
backend is a lowering, and touches nothing above it.

## The syntax

Six rules, and that is the whole language:

1. Keywords are English words at the start of a line.
2. A block opens with `:` and its contents are indented.
3. Indentation is spaces. Tabs are refused, because a tab is a different width
   in every editor and the same file would parse differently.
4. `#` starts a comment.
5. Strings are quoted.
6. Lists are comma-separated.

### Loading data

```econ
data "macro.csv"
```

```econ
data load "macro.xlsx":
    sheet = "Sheet1"
    missing = ".", "NA", "-"
```

CSV, TSV, Excel, Parquet, Stata `.dta` and JSON.

### Declaring time

```econ
set time:
    variable = year
    frequency = quarterly
```

Declaring it is what turns on the checks: a repeated time value is **refused**
(and suggests declaring a panel instead), while gaps and unsorted rows are
reported as warnings rather than silently estimated over.

### A model

```econ
model ols baseline:
    y = gdp
    x = inflation, unemployment
```

| Option | Meaning |
|---|---|
| `y` | the dependent variable |
| `x` | the regressors, comma separated |
| `intercept` | `yes` or `no`; `yes` by default |
| `vcov` | `nonrobust`, `HC0`–`HC3`, `robust`, or `cluster` |
| `cluster` | the variable to cluster standard errors on |
| `weights` | a variable of observation weights |
| `engine` | which backend estimates this model |

`vcov = robust` is stored as **HC1** explicitly, because statsmodels, Stata and
R all mean HC1 by "robust" for OLS — leaving the word unresolved would let three
engines quietly mean three things.

### Commands

```econ
explain baseline        # the model in words, not syntax
show code baseline      # the native code that will actually run
translate baseline      # the same model in all six backends
dryrun baseline         # interpret and generate, execute nothing
export baseline "table1.tex"
```

## Seeing the generated code

EconEnv is never a black box. `show code` prints what the engine receives:

```
# baseline — generated python code
import statsmodels.formula.api as smf

model = smf.ols("gdp ~ inflation + unemployment", data=data)
result = model.fit(cov_type="HC3")
print(result.summary())
```

and `translate` shows every backend at once, generated by the **same**
compilers that execute — so the table cannot drift from what runs.

Where a backend cannot do exactly what was asked, the generated code says so
rather than substituting quietly:

```
' note: HC3 was requested. EViews' cov=white is the HC1 form,
'       so these standard errors are not the same estimator.
equation robust_se.ls(cov=white) gdp c inflation unemployment
```

That is the rule the whole design turns on: **no silent substitution** — not of
an engine, not of an estimator, not of a covariance.

## Dry running

```python
lang.run(source, dry_run=True)
```

Nothing is loaded and nothing is estimated. You get the interpretation and the
generated code, which is what makes the language teachable — and it works even
when the data file does not exist yet.

## Errors

An error message is part of the language, not an afterthought. Every one
carries a code, the line, a caret, and where possible the corrected line:

```
E101 — Variable not found

  'GDP' is not in the active dataset.
  at line 4, column 5

        y = GDP
        ^

  Did you mean:
    gdp

  Available:
    year
    gdp
    inflation

  Suggested fix:
    y = gdp
```

The codes are grouped by which layer failed:

| | |
|---|---|
| `E1xx` | data |
| `E2xx` | syntax |
| `E3xx` | semantic |
| `E4xx` | econometric |
| `E5xx` | backend |
| `E6xx` | execution |
| `E7xx` | capability |
| `E8xx` | export |

An estimator the language does not implement yet is `E701` — a **capability**
error naming what is available — not a syntax error, because the word itself is
perfectly good.

## What it does not do yet

This is the first vertical slice, and deliberately narrow: **OLS only**. The
architecture is meant to be proved before it spreads.

Not here yet: panel and IV and GMM, logit, unit-root and cointegration tests,
VAR and ARDL and GARCH, plots, reports, `engine = auto` routing, and the
`.econ` project file. Each is a lowering plus a method registration on top of
the machinery that now exists.
