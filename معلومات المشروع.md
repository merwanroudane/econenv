أنت Senior Python Package Architect وJupyter/IPython Extension Developer ومتخصص في interoperability بين البرامج الإحصائية والاقتصاد القياسي.

أريد منك تطوير مشروع مفتوح المصدر احترافي وكامل، وليس مجرد Prototype تعليمي.

## معلومات المشروع

**Project Name:** EconEnv  
**Author:** Dr Merwan Roudane  
**GitHub Repository:** https://github.com/merwanroudane/econenv

### الفكرة الأساسية

أريد تطوير بيئة موحدة داخل Jupyter Notebook تسمح للباحث باستخدام:

- Python
- R
- Stata
- EViews

داخل **نفس الـNotebook**.

الهدف النهائي أن يكون Python/IPython هو الـmain kernel، بينما يتم التعامل مع R وStata وEViews كـexecution engines مرتبطة به.

أريد أن يستطيع المستخدم الانتقال بين اللغات داخل Notebook واحد باستخدام Cell/Line Magics مناسبة، دون الحاجة إلى فتح أربعة برامج منفصلة أو تغيير الـNotebook Kernel يدويًا.

# 2. Architecture Decision

لا أريد في الإصدار الأول إنشاء Jupyter Kernel جديد من الصفر.

ابدأ بـ:

**Python Package + IPython Extension**

بحيث تكون المعمارية:

JupyterLab / Jupyter Notebook  
→ IPython / Python Kernel  
→ EconEnv  
→ Python native  
→ R Adapter  
→ Stata / PyStata Adapter  
→ EViews / py2eviews Adapter

صمم المشروع بطريقة تسمح مستقبلًا بإضافة:

- MATLAB
- Julia
- SAS
- Gretl
- Dynare
- GAUSS
- Ox
- RATS

دون إعادة كتابة الـcore.

استخدم Adapter/Plugin Architecture مناسبة.

# 3. تجربة المستخدم المطلوبة

أريد في النهاية أن يستطيع المستخدم تثبيت EconEnv، تحميل extension مرة واحدة، ثم استخدام:

Python بصورة طبيعية.

ثم R من خلال line/cell magic.

ثم Stata باستخدام التكامل الرسمي لـPyStata قدر الإمكان.

ثم EViews باستخدام line/cell magic نطورها نحن إذا لم يوجد مقابل رسمي مناسب.

الهدف:

**One Notebook. Multiple Econometric Engines.**

لا تعيد اختراع `%stata` أو `%%stata` إذا كان PyStata يوفرها رسميًا بصورة أفضل.

وبالنسبة لـR، لا تنشئ Magic جديدة باسم يتعارض مع Magic رسمية موجودة دون اكتشافها والتعامل معها.

أعتبر المشروع ناجحًا في مرحلته الأساسية عندما يستطيع الباحث فتح Notebook واحد واستخدام:

- persistent engines
- data exchange
- diagnostics
